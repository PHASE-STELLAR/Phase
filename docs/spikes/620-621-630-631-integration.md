# Spikes 620 / 621 / 630 / 631: implementation and acceptance evidence

Issues: #483, #484, #493, #494. Flags: phase-174, phase-175, phase-176, phase-177 respectively. All default off. This document distinguishes implemented behavior from deployment acceptance. **Live acceptance is not complete; do not treat this branch as a completed production KYC system or tax product.**

## Implemented closed loops

- Link → strict parser → session capture → wallet connection → explicit review → live target lookup → offer/quest/collection screen. Offer decisions require a signed, bounded-time seller proof while the new flow is enabled. Navigation never auto-signs, accepts, claims, transfers or calls the faucet.
- Phone viewport → readable targets → scrollable cockpit → controls sheet → focus trap/Escape → opener restored. Prompt state remains in the page while sheets open/close. Pointer capture supports touch drawing without disabling scrolling outside the canvas.
- Claim → server-computed effective amount → fresh sanctions adapter → amount threshold → persisted provider credential → existing payout path. Turnstile, governance denial, sybil and claim replay defenses remain independent. The claim-bounty alias delegates to the same gate and preserves Retry-After.
- Confirmed faucet/bootstrap receipt or marketplace agreement → durable SQLite evidence → signed export authorization → frozen sequence snapshot → bounded CSV pages → downloaded artifact. Agreements are explicitly unverified; missing basis and fiat values are never fabricated.

## Replay, ordering, errors, and clocks

| Surface | Authority and retry behavior |
| --- | --- |
| Incoming links | Versioned session record; 15-minute wall-clock expiry; strict reparse on restore; review followed by fresh server lookup. It grants no mutation capability. |
| Offer decisions | Signed seller proof, five-minute clock window, BEGIN IMMEDIATE with current pending/active/expiry checks. Offer + listing + reporting records commit together. A second decision returns 409/current_status. Every other pending offer for a sold listing is rejected. |
| KYC webhooks | Exact-byte timestamped HMAC, unique event ID, expectedVersion CAS in BEGIN IMMEDIATE. Retry of an event ID is idempotent; another stale event returns 409/current_version. Expired credentials cannot satisfy a large claim. |
| Sanctions | Live HTTPS response must be fresh and not expired. No process-local or stale-on-error clearance. 3s timeout; unavailable/malformed/stale screening is 503/Retry-After:60. Sanctions block is 451; missing identity is 403/KYC_REQUIRED. |
| Tax records | Unique source event key; different content under an existing key is a conflict. Immutable sequence plus `(occurred_at,seq)` pagination separates wall-clock ordering from durable insertion order. Verified receipts require a hash. |
| Exports | Wallet/network/range/policy/expiry/nonce bound SEP-53 proof. Signature is verified before consuming a nonce; atomic nonce uniqueness rejects replay (409). 60 exports/minute per authenticated wallet; 429 carries Retry-After. |
| Existing faucet | Existing pending receipt + cooldown/claim rules remain authoritative. Pending state now also preserves exact amount and token contract for reporting after a restart. A reporting failure after confirmed bootstrap does not release the payout claim for duplicate funding. |
| Existing CRDT / JSON paths | No new writes to signal drafts, vector clocks, referral attribution or sidecar queues. Their existing merge/CAS/locking rules remain unchanged. |

No new endpoint invents ETag/If-Match semantics for resources without versions. Existing signal 409/412, CRDT state-vector and parent-version contracts remain unchanged. New UI keeps inputs on failure and honors numeric Retry-After. Gate #13 normalization/signing code is preserved.

## Contract drift and storage migration

No WASM upload, upgrade, redeploy, issuer change or contract-ID change is needed. New listings record the configured contract ID instead of resolving it again at export time; old listings without provenance use an explicit unknown-contract asset key. Pending faucet receipts retain the token contract and exact paid amount. Historical pending records without those fields are not assigned guessed amounts or assets. Existing `get_config`, classic issuer/SAC validation, `token_uri?c=` and gateway health/read fallbacks remain in their original boundaries.

SQLite adds `compliance_credentials`, `compliance_webhooks`, `tax_events`, `tax_export_nonces`, `tax_export_rate`, indexes, and an additive nullable `listings.contract_id` column. Schema creation/migration is idempotent and serialized with BEGIN IMMEDIATE; the busy timeout is configured before the WAL transition so concurrent first-open processes do not bypass it. No destructive migration/backfill is performed. SQLite busy timeout is bounded at five seconds. As with existing SQLite storage, multi-instance consistency requires a shared durable database/volume; Vercel per-instance tmp storage is not a shared database. This branch does not claim to solve that deployment limitation.

Rollback: unset both server and public feature variables, rebuild/restart. New routes return 404 where applicable, the existing pages stop mounting new flows, and evidence/credentials stay inert on disk. Do not remove audit history on rollback. Public association deployment changes also need cache expiry (five minutes).

**Still required before closing all issue acceptance checkboxes:**

1. Public testnet receipt chain covering Friendbot → trustline → fund → act → verify → index → UI, with transaction hashes and the actual deployment IDs. This checkout contains only `.env.local.example`, not configured signer/provider credentials. No receipt hashes are invented in this document.

3. Provider sandbox wallet-binding ceremony, real sanctions adapter integration/freshness/revocation exercises, credential/hash-key rotation, retention policy, and durable shared deployment storage. Mock CI success is not vendor/OFAC integration evidence.
4. External historical receipt/FX/basis reconciliation and general fungible lot accounting/1099-DA mapping if those are required for closing #494. Current export is deliberately labeled testnet evidence, not a completed filing product.
5. Full upstream baseline repair or maintainer acceptance of existing failures. Untouched upstream main at 11cb3bc9 reproduces 18 failed files / 54 failed tests / 153 TypeScript errors. The baseline also could not render the requested pages before the targeted compile/context repairs in this branch.
6. Live primary-RPC/Horizon/gateway failure injection and real device wallet returns. Existing failover/bulkhead tests plus new provider-failure tests are local evidence, not a claim that a live dependency was killed.

These external requirements keep the PR in draft. The implementation does not alter contracts or signal/CRDT storage merely to manufacture irrelevant migration or concurrency claims.
