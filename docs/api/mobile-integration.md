# Mobile integration APIs

All feature flags default off. Error codes are stable machine values; new UI translates through `pickCopy(lang).integrations` (English/Spanish). Responses containing identity/reporting context use `private, no-store`.

## Incoming links — phase-175

`GET /api/links/resolve?link=<encoded same-origin /link path or custom URI>` returns `{intent, href, context}`. Accepted kinds: `collection/<positive ID>`, `quest/<quest ID>`, `offer/<listing ID>/<offer ID>`. Optional `ref` is an eight-character referral code; `recipient` must pass Stellar address checksum validation. Neither parameter authorizes an action. Codes: disabled 404, malformed 400, missing/expired/decided offer or unknown quest 410. Existing collection metadata and its canonical URL remain generated by Chamber.

`GET /.well-known/assetlinks.json` / `apple-app-site-association` return configured app associations with JSON/CORS headers. Empty configuration produces empty associations; it does not prove OS verification. Native application signing fingerprints and app IDs are deployment inputs. `/link` is the pasted-URI browser fallback.

When phase-175 or phase-177 is active, deciding an offer requires `{wallet, action, timestamp, signature}`. Sign the existing signal-proof payload `{title: "market:<listing>:<offer>:<action>", body: wallet, timestamp}` using `signSignalPayload`. Five-minute time bounds apply. The decision is a SQLite transaction; an overlapping writer receives 409/current_status. Offer acceptance records an agreement, not NFT transfer or chain settlement. Rejected/expired/self-dealing offers cannot enter the new acceptance path.

## Compliance — phase-176

The faucet (including claim-bounty delegation), classic bootstrap, trustline relay, and x402 demo verification/settlement use `complianceGate` before credit or submission. Reward thresholds use the server-computed amount including daily multipliers, never a client-provided amount. Batch trustlines screen every operation source and reject non-changeTrust operations while enabled. Demo x402 shims are forbidden in live mode; unsigned demo tokens cannot establish verified live payments.

| Status | Code | Recovery |
| --- | --- | --- |
| 400 | INVALID_AMOUNT / INVALID_WALLET | Correct input; no credit occurred |
| 403 | KYC_REQUIRED | Complete provider verification; retry unchanged claim |
| 451 | SANCTIONS_BLOCKED | No credit or automatic retry |
| 503 | SCREENING_UNAVAILABLE | Honor Retry-After: 60; keep user input |

`POST PHASE_SANCTIONS_URL` receives `{wallet, operation, network}` with server bearer authorization. Expected strict result: `{sanctions: "clear"|"blocked", checkedAt: <ms>, expiresAt: <ms>}`. No stale-on-error cache or client overrides. Use a provider-owned adapter for vendor-specific APIs; there is no bundled OFAC feed or vendor contract.

`POST /api/compliance/webhook` requires `x-phase-timestamp` and `x-phase-signature` over exact raw bytes. Payload:

```json
{"eventId":"provider_event_001","wallet":"<valid G address>","subject":"provider subject ID","status":"verified","expiresAt":1800000000000,"expectedVersion":0}
```

Unknown fields (including identity documents) are rejected. Success: `{ok:true,replay:false,version:1}`. Identical event ID redelivery is idempotent with `replay:true`; stale expectedVersion returns 409/current_version. Invalid signature is 401; invalid event is 400. Persisted credentials contain keyed hashes, status, expiry and version, not raw wallet/subject/PII. Provider integration must prove wallet binding before posting a verified status. Hash-key rotation requires re-verification; webhook-key rotation requires coordination with the adapter.

## CSV — phase-177, testnet only

`POST /api/tax/export` body is `{claims, signature}`. Claims: `{wallet, from, to, policy:"FIFO"|"HIFO", exp:<epoch seconds>, nonce:<16–128 character unique ID>}`. `from/to` are UTC ISO strings, `to` exclusive, maximum ten years. Sign `taxExportMessage(claims, testnetPassphrase)` via wallet `signMessage`; server verifies the SEP-53 envelope. A signature expires within five minutes and is consumed once. Altered wallet/range/policy/network fails 401; replay is 409; invalid range is 400. Flag off is 404; mainnet is 503. Signed exports are limited to 60 per minute per wallet; 429 includes Retry-After. Bodies are bounded at 4 KiB (export/provider responses) and 8 KiB (webhooks), even without Content-Length.

Success: streamed RFC 4180 CSV, safe attachment filename, X-Tax-Snapshot, no-store. Numeric values are canonical decimal PHASELQ, independent of UI locale; arbitrary cells receive formula neutralization. CSV columns include event ID, UTC time, kind, asset, amount, basis, proceeds, gain, royalty income, receipt hash, flags, policy, recomputation hash. Missing basis/FX remain blank; unverified and wash-flagged rows do not contribute proceeds or royalty income. Confirmed reward quantities do not imply an invented fiat FMV. FIFO/HIFO apply only to recorded indivisible NFT lots; this is not general fungible-asset lot accounting or a completed 1099-DA form.

The export covers evidence recorded after enabling phase-177. Historical marketplace agreements without receipts, contributor allocations without payouts, treasury refills and AI infrastructure estimates are not personal taxable proceeds. No automatic backfill guesses acquisition basis. CSV retry signs a fresh nonce against the new snapshot.
